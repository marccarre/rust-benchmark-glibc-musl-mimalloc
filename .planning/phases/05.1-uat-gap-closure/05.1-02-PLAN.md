<objective>
Close UAT Gap 2 (ORCH-04): the `Aggregate report` job in `.github/workflows/bench.yml` fails at the `Run aggregator` step because the preceding `Reorganize artifacts` step's `mv` patterns target the wrong directory level. `actions/upload-artifact@v4` preserves the subdirectory structure declared in its multi-line `path:` block (so per-cell artifacts contain `results/{alloc}-{env}-seed*.json` and `meta/{alloc}-{env}.json` as nested subdirs); `actions/download-artifact@v4 merge-multiple: true` PRESERVES that structure under `./artifacts/`. The current `mv artifacts/*-seed*.json results/ 2>/dev/null || true` and `mv artifacts/*.json meta/ 2>/dev/null || true` patterns target the empty TOP level of `./artifacts/`, both fail, both failures are silently swallowed by `2>/dev/null || true`, and the freshly mkdir'd `results/` directory remains empty when `just ci-aggregate` runs.

Purpose: Make a one-step fix to `.github/workflows/bench.yml` (the Reorganize step at lines 241-246 region) so:
  1. The mv source paths are corrected to `artifacts/results/*.json` and `artifacts/meta/*.json` (the actual subdirectory paths preserved by upload-artifact@v4).
  2. The silent `2>/dev/null || true` clauses are dropped so a real "no such file" path-drift surfaces as a hard fail in the workflow log.
  3. A leading `ls -la artifacts/` debug print is added so the next time GHA artifact-action behavior shifts, the failure is self-documenting.
  4. The trailing `ls -la results/ meta/` post-state print is preserved (and de-silenced) so the post-fix state is visible.

This plan is intentionally narrow: ONE file (.github/workflows/bench.yml), ONE step (Reorganize artifacts), ZERO source-code or schema changes. It does NOT touch the per-cell upload step (no smoke-test impact), does NOT touch the aggregator binary (no Rust changes), does NOT touch any other workflow job.

Output:
