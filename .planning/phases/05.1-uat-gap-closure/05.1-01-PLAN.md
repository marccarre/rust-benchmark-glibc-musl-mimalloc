<objective>
Close UAT Gap 1 (REPR-01): the Phase 3 D-09 `RUSTFLAGS=-C target-cpu=x86-64-v3` baseline emits AVX2/BMI2 instructions that Apple Silicon's Rosetta-2 emulator does not reliably execute, causing all 18 cells of `just bench-all-smoke` to SIGSEGV (exit 139) on macOS arm64 hosts. v1.0 GHA on real x86-64 Linux passes 18/18; the bug is purely a host-emulator instruction-set gap.

Purpose: Restore REPR-01 ("a fresh user follows README and reproduces the matrix") for Apple Silicon hosts without breaking the v1.0 GHA invariant ("all 18 cells pass on ubuntu-24.04 with v3 codegen"). The fix is a Dockerfile build-arg override + a justfile auto-detect knob + a README documentation update — no source-code or v1 schema changes.

Output:
  - Six Dockerfiles converted from unconditional `ENV RUSTFLAGS="..."` to a `ARG RUSTFLAGS_OVERRIDE="" / ENV RUSTFLAGS="${RUSTFLAGS_OVERRIDE:--C target-cpu=x86-64-v3}"` pattern (default unchanged → CI behavior preserved).
  - `justfile` `build` recipe forwarded a `--build-arg RUSTFLAGS_OVERRIDE=...` value computed from `BENCH_TARGET_CPU` (user-supplied) OR auto-detected on Apple Silicon (arm64+Darwin → x86-64-v2).
  - Optional `bench-all-smoke-apple-silicon` convenience recipe (sets BENCH_TARGET_CPU=x86-64-v2 then re-invokes bench-all-smoke).
  - README §Troubleshooting Apple Silicon entry rewritten + README §Reproducibility cross-link.
</objective>

Builder-stage contract (all six docker/*.Dockerfile):

    ENV RUSTFLAGS="-C target-cpu=x86-64-v3"                                    (alpine, debian-slim, distroless-cc, wolfi)

    ARG RUSTFLAGS_OVERRIDE=""

  Default semantics: when --build-arg RUSTFLAGS_OVERRIDE is absent or empty, ${VAR:-default} expands to the v3 default (preserves v1.0 CI invariant).

justfile build-recipe contract:
- New env var: BENCH_TARGET_CPU (user-supplied; e.g. "x86-64-v2" or "x86-64-v3" or "native"). Empty → auto-detect.
- Auto-detect rule: when BENCH_TARGET_CPU is unset AND `uname -m` returns "arm64" AND `uname -s` returns "Darwin", fall back to "x86-64-v2".
- Otherwise (real x86-64 Linux/macOS host, or BENCH_TARGET_CPU explicitly set): use BENCH_TARGET_CPU verbatim, or pass empty string when the auto-detect did not fire on a non-arm64 host (so the Dockerfile default fires unchanged).
- Wire into the existing `docker buildx build` invocation as `--build-arg RUSTFLAGS_OVERRIDE="${OVERRIDE_VALUE}"` where OVERRIDE_VALUE is either "" (use Dockerfile default) or "-C target-cpu=${BENCH_TARGET_CPU}" (with the +crt-static suffix preserved for distroless-static and scratch).

  Critical detail: the +crt-static suffix is set inside the Dockerfile, NOT in justfile. So the override value the justfile forwards is JUST the `-C target-cpu=...` portion; the Dockerfile prepends/concatenates correctly because the override REPLACES the entire RUSTFLAGS string when present.

  Either:
  (a) The override mechanism uses ${RUSTFLAGS_OVERRIDE:--C target-cpu=x86-64-v3 -C target-feature=+crt-static} — meaning the override REPLACES the whole flag string, and the justfile must therefore append +crt-static when env is distroless-static or scratch; OR
  (b) The Dockerfile splits target-cpu and target-feature into separate ENV pieces, with the override replacing only target-cpu.

  Choose (a): simpler Dockerfile diff, the justfile already knows the env name and can synthesize the full override string. The justfile concatenates "-C target-cpu=${BENCH_TARGET_CPU}" with " -C target-feature=+crt-static" when env is in {distroless-static, scratch}.
