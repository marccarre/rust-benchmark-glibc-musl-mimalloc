SPMC tick (1 producer + N cloned receivers race for messages):
- `let (s, r) = crossbeam_channel::bounded::<ChannelPayload>(cfg.capacity);`
- Use `std::thread::scope`: spawn `cfg.consumers` consumers each holding `let r = r.clone()`. Each consumer drains via `while let Ok(msg) = r.recv() { std::hint::black_box(&msg); drop(msg); }`

- Producer (this thread): `for seq in 0..cfg.objects_per_tick { let size = sample_payload_size(...); let data = vec![0u8; size].into_boxed_slice(); s.send(ChannelPayload { seq, data }).unwrap(); }`

- `match h.join() { Ok(v)=>..., Err(p)=>std::panic::resume_unwind(p) }` — same as Multithread pattern

MPSC tick (N cloned senders + 1 receiver in this thread):
- Same channel construction
- Spawn `cfg.producers` senders each holding `let s = s.clone()` and a per-thread `SmallRng::seed_from_u64(cfg.seed.wrapping_add(p as u64))` (mirrors Multithread seed-per-thread pattern)
- Each sends `cfg.objects_per_tick / cfg.producers as u64` messages
- Drop original sender after spawn
- Consumer (this thread): `while let Ok(msg) = r.recv() { ... }`

MPMC tick: combine — N senders + M receivers, both cloned. Drop both originals between spawn and join.

Set `allocations_per_tick = cfg.objects_per_tick` (one Box<[u8]> per send).

Defeat DCE: each producer payload allocation must include `data[size / 2] = (seq & 0xFF) as u8;` BEFORE sending (Phase-1 PITFALLS §1.2 pattern). Each consumer must `std::hint::black_box(&msg)` before drop.

CRITICAL anti-pattern from RESEARCH.md §Pitfall 2: producers run flat-out, no `thread::sleep` between sends — this is the documented decision for SCEN-03/04/05.

Each scenario's `name()` returns `"spmc"`, `"mpsc"`, `"mpmc"` respectively. `config_json()` serializes `self.cfg`. `setup()` returns Ok. `teardown()` is default.
