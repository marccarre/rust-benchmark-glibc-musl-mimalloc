# Phase 10 — UI Design Contract

> Visual and interaction contract for direction-marker glyphs (`↑` U+2191 / `↓` U+2193) wired into REPORT.md per-scenario column headers and `report/index.html` Plotly chart axis labels via `axes::Direction::arrow()` (Phase 6 SSoT). Generated by gsd-ui-researcher; verified by gsd-ui-checker.

This is a **decoration phase**, not a layout phase. There is no new viewport, no new component, no new interaction. Every visual surface Phase 10 touches is already shipped — the per-scenario tables in `markdown.rs::emit_per_scenario_tables` and the four chart axis titles in `index.html.tmpl` (throughput / latency-heatmap colorbar / RSS-over-time / A-B comparison). Phase 10 changes column-header bytes and inserts a one-line legend row above each per-scenario table; data cells stay numeric (DIR-05 byte-stable contract).

**Inheritance:** All design tokens (spacing, typography, color, font stack) are reused verbatim from the v1.0 `:root` block in `crates/alloc-bench-aggregator/templates/index.html.tmpl` (lines 22-58). No new CSS variables, no new typography tokens, no new color tokens. Phase 10 introduces ZERO new tokens. The novel surface is one HTML primitive — `<span aria-label="...">↑</span>` — and one Markdown convention — the legend row pattern.

**Phase 10 introduces ZERO new spacing tokens, ZERO new CSS rules.** The legend row in REPORT.md is plain text on its own line — Markdown line spacing applies. The HTML axis labels, table headers, and `<span aria-label="...">` wrappers all sit inside existing chart containers and table cells whose padding/margins are already specified.

**Glyph kerning:** the column-header pattern is `{label}{single-space}{arrow}` (e.g. `throughput ↑`). The single ASCII space (U+0020) — not `&nbsp;`, not `\t` — is the inter-glyph separator, both in REPORT.md output and in the Plotly axis-title strings. This matches the verbatim ROADMAP DIR-01 examples (`Throughput ↑ (ops/s)`, `Latency p99 ↓ (ns)`, `Peak RSS ↓ (MB)`).

**Legend-row pattern:** in REPORT.md, the legend sits on its own line, with one blank line above (separating from `## {scenario}`) and one blank line below (separating from the table). The interpunct `·` (U+00B7) is flanked by single ASCII spaces: `↑ higher is better · ↓ lower is better · ⚠ suspect run`. NO trailing punctuation. NO bold / italic / code-fence wrapping. NO leading list-marker.

**Exceptions:** none. Phase 10 is a pure-content phase — no spacing changes.

**Glyph rendering discipline:**

- The `↑` (U+2191) and `↓` (U+2193) glyphs are rendered at the same size and weight as the surrounding column-header / axis-label text. NO CSS bump (`font-size: 1.2em`), NO bold-only override, NO color override. Reason: the glyphs are direction markers, not call-to-action icons; visual emphasis would falsely suggest interactivity.
- The `·` (U+00B7 MIDDLE DOT, NOT `•` U+2022 BULLET, NOT `.` U+002E FULL STOP) renders inline at body weight in the legend row.
- The `⚠` (U+26A0 WARNING SIGN) in the legend already ships in v1.0 (REPORT.md `⚠ suspect`, HTML `⚠ ` prefix at index.html.tmpl line ~398). Phase 10 reuses it verbatim — no rendering change.

**Markdown side (REPORT.md):**

- Column-header literal: `| allocator | throughput ↑ | p50 ↓ | p95 ↓ | p99 ↓ | p999 ↓ | peak RSS ↓ |` — the `allocator` column stays plain (it's a label, not a measurement; CONTEXT decision row).
- Legend-row literal: `↑ higher is better · ↓ lower is better · ⚠ suspect run` — exact bytes pinned for golden-test stability in Phase 11. NO surrounding asterisks, NO em-dash flanking, NO `>` blockquote prefix.

**HTML side:**

- Plotly axis-title strings emit the same `{label} {arrow}` pattern, then wrap each glyph in `<span aria-label="...">` at render time. Plotly v2.35.3 `layout.{xaxis|yaxis}.title.text` accepts HTML markup (verified via Plotly docs).
- Dashboard per-scenario table headers (line ~851 array) are server-injected as a JSON array of strings — JS no longer hard-codes `"throughput"`, `"p50"`, etc.

**Word count:** legend row is 41 ASCII characters + 3 multibyte glyphs + 2 multibyte interpuncts (NOT counting bytes — counting display columns). Single line; renderer-wraps only on extremely narrow viewports (mobile dashboard < 320px).

| Accent (10%) | `#0969DA` (`--color-accent`) | Reserved exclusively for: (a) browser-native focus outline on `<select>` (line 114) and on `<details><summary>`; (b) Plotly modebar hover button outline. NOT used for any direction-marker glyph. NOT used for the legend row. |
| Destructive | `#CF222E` (`--color-destructive`) | Reserved for `.suspect-note` span (line ~220) and `#diff-banner` (line ~299). Phase 10 does NOT use destructive directly — the `⚠` glyph in the legend row inherits default text color, NOT destructive red. |
| Text | `#1F2328` (`--color-text`) | Default text color. Direction-marker glyphs (`↑` / `↓`), legend row (`↑ higher is better · ↓ lower is better · ⚠ suspect run`), and column-header text all render at `#1F2328`. |
| Text muted | `#656D76` (`--color-text-muted`) | Reserved (existing usage on caption text + sidebar `.hint` at line 118). Phase 10 does NOT use muted for the legend — full text color is required because the legend is **functional disambiguation**, not metadata. |
| Border | `#E1E4E8` (`--color-border`) | Existing 1px borders unchanged. |

**Accent reserved for:** browser-native focus outline on the existing sidebar `<select>` controls and `<details><summary>` disclosures, plus Plotly's default modebar button hover styling. NOT used in any Phase 10-introduced surface. The `↑` / `↓` glyphs are NOT accent-colored (they would falsely suggest sortable / clickable headers).

**Glyph color rationale (no semantic coloring):**

- The arrows are **direction markers, not status signals**. Coloring `↑` green (good) and `↓` red (bad) would falsely imply that "higher throughput" is morally good while "lower latency" is morally bad — but lower latency is what the user wants. Both arrows mean "this direction is better"; the difference is which direction. Default text color preserves that semantic neutrality.
- The legend row's `⚠` does NOT render in destructive red. The `⚠` is the same character v1.0 ships in REPORT.md and in the HTML dashboard prefix (line ~398) — both render at default text color today; Phase 10 preserves that.

**WCAG color-contrast verification (text on background, all WCAG 2.1 SC 1.4.3):**

- REPORT.md `↑` / `↓` glyph text `#1F2328` on white `#FFFFFF` → 14.4:1 (AAA Normal + AAA Large)
- HTML chart axis-title with glyph `#1F2328` on white → 14.4:1 (AAA)
- HTML dashboard `<th>` text with glyph `#1F2328` on `#F4F5F7` (secondary) → 13.8:1 (AAA)
- Legend row `↑ higher is better · ↓ lower is better · ⚠ suspect run` `#1F2328` on white → 14.4:1 (AAA)
- Plotly colorbar title with `↓` glyph `#1F2328` on white → 14.4:1 (AAA)

All glyphs and labels pass WCAG AAA at body size — no minimum-size override needed for the `↑` / `↓` characters.

**Tone & voice:**

- Legend row uses lowercase sentence fragments, present tense, no punctuation: `higher is better`, `lower is better`, `suspect run`. Matches the existing v1.0 `*(suspect)*` annotation style — terse, factual, no first-person, no marketing.

- Chart axis labels follow Plotly conventions: lowercase noun + arrow + parenthesized unit. `throughput ↑ (per scenario unit)` is shorter and more scannable than `Throughput (higher is better, per scenario unit)`.

**Aria-label copy (assistive tech):**

```markdown
| allocator | throughput ↑ | p50 ↓ | p95 ↓ | p99 ↓ | p999 ↓ | peak RSS ↓ |
|---|---|---|---|---|---|---|

| mimalloc | 138.2 ticks/s | 6900 ns | 7300 ns | 7900 ns | 12200 ns | 25600 kB |

```

- Blank line between `## {scenario_name}` and the legend row
- Blank line between the legend row and the table header
- Blank line after the table (existing v1.0 convention; line 238 of `markdown.rs`)

### Visual hierarchy (REPORT.md)

`## {scenario}` heading (level 2) → legend row (body text, single line, glyph-prefixed bullets) → table header (with arrow glyphs) → data rows (numeric, NO arrows) → blank line → next scenario.

The legend row is **textually adjacent** to the table it disclaims — the user's eye can read both in a single glance. Placing the legend once at the top of REPORT.md (instead of repeating per scenario) was rejected: each per-scenario table is a self-contained reading unit, and the user often jumps directly to a scenario via TOC.

### HTML per-chart axis-title structure (after Phase 10)

Plotly chart layout for the throughput chart (illustrative — same pattern for latency-heatmap colorbar, RSS-over-time, and A/B):

```js
{
  yaxis: {
    title: {
      text: 'throughput <span aria-label="higher is better">↑</span> (per scenario unit)',
      // Plotly v2.35.3 accepts HTML in title.text strings (verified)
      font: { size: 12, color: '#1F2328' }
    }
  }
}
```

The HTML wrapping is performed server-side at render time — the Rust `html.rs` builder emits the literal `<span aria-label="higher is better">↑</span>` substring directly into the Plotly layout JSON. JS code never re-derives the glyph table from `axes.rs`.

## Accessibility

**Semantic HTML:**

- `<span aria-label="higher is better">↑</span>` and `<span aria-label="lower is better">↓</span>` — non-focusable inline elements; visually identical to a bare arrow glyph; assistive tech announces the `aria-label` instead of the Unicode-name fallback ("UPWARDS ARROW" / "DOWNWARDS ARROW").
- Column headers stay as `<th>` in the dashboard table (existing markup); no role override.
- Chart axis-title strings are emitted as Plotly `layout.{xaxis|yaxis}.title.text` HTML — Plotly v2.35.3 inserts them into the SVG `<text>` element. Screen readers announce SVG `<text>` content; the inline `<span aria-label="...">` is preserved through Plotly's HTML-in-title pipeline (verified).

**Headings hierarchy:** unchanged from v1.0. Phase 10 adds no new headings.

**ARIA:**

- `aria-label="higher is better"` (3 words, lowercase, no period) wraps every `↑` glyph in HTML.
- `aria-label="lower is better"` (3 words, lowercase, no period) wraps every `↓` glyph in HTML.
- The `⚠` glyph in the HTML legend inherits its existing v1.0 announcement ("WARNING SIGN" Unicode-name lookup); no additional aria-label is added (CONTEXT decision row — Markdown a11y is provided by the legend disclaimer text itself, not by per-glyph wrappers).
- NO `role="presentation"` or `aria-hidden="true"` on the glyph spans — the glyphs DO carry semantic meaning (direction marker), so they must be announced to assistive tech with the `aria-label`-supplied phrase rather than hidden.

**Markdown a11y:**

- REPORT.md has no native a11y semantics. The legend row above each table IS the disclaimer text — assistive tech reading REPORT.md announces the legend before the table, so the user knows the arrows are direction markers before encountering them in headers.
- DIR-04 only mandates HTML a11y (`<span aria-label="...">`); Markdown side stays plain glyph text.
- Adding raw `<th>` HTML blocks inside REPORT.md to attach aria-label spans was rejected — GitHub's GFM renderer does not render embedded HTML reliably across all surfaces (PR review, file view, raw view), and the legend-row approach achieves equivalent screen-reader disambiguation.

**Color contrast:** see **Color** section above. All glyphs render in default text color `#1F2328` against white (14.4:1) or against secondary `#F4F5F7` (13.8:1) — both pass WCAG AAA at body size.

**Color-blind safety:**

- The arrow glyphs carry shape-based meaning, not color-based. `↑` and `↓` are visually distinguishable regardless of color-vision deficiency.
- The legend row uses textual cues (`higher is better` / `lower is better` / `suspect run`) — color-blind-safe by construction.
- The `⚠` warning sign is shape-based (triangle with exclamation) — color-blind-safe.

**Focus management:** no new focusable elements. The `<span aria-label="...">` wrapper is non-focusable by default. Tab order is unchanged.

**Screen-reader experience:**

- REPORT.md per-scenario announcement: "scenario name heading level 2; UPWARDS ARROW higher is better MIDDLE DOT DOWNWARDS ARROW lower is better MIDDLE DOT WARNING SIGN suspect run; table; allocator UPWARDS ARROW throughput..." — without `aria-label` wrapping, the arrows announce as their Unicode names. Combined with the legend row disclaimer, the meaning is unambiguous.
- HTML dashboard announcement: "allocator; throughput, higher is better; p50, lower is better; ..." — the `aria-label` substitution makes the announcement read naturally as English prose rather than Unicode names.
- HTML chart axis announcement: "throughput, higher is better, per scenario unit" — same pattern; the `aria-label` substitutes for the Unicode-name fallback.
