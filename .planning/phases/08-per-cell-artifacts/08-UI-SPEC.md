# Phase 8 — UI Design Contract

> Visual and interaction contract for per-cell recommendation cards (`## Top 10 cells` section in REPORT.md, `<section class="top-n-recommendations">` in index.html, and ten standalone `.md`/`.html` fragments per `report/recommend-{rank:02d}-{alloc}-{env}.{md,html}`). Generated by gsd-ui-researcher; verified by gsd-ui-checker.

This phase ships **prose cards** rendered via two tinytemplate files (`recommend-cell.md.tmpl` and `recommend-cell.html.tmpl`) driven by the same `CellRecommendation` struct. The visual surface inherits from the existing v1.0 design system already declared in `crates/alloc-bench-aggregator/templates/index.html.tmpl` lines 21-215 — no new CSS variables, no new component classes (beyond the `.recommend-card` namespace hook), no new typography tokens.

## Design System

| Preset | not applicable (Rust-rendered static dashboard, file://-friendly per D-02) |
| Component library | none (vanilla HTML inside a tinytemplate-rendered string) |

**Source of truth:** the existing `:root` CSS variable block in `crates/alloc-bench-aggregator/templates/index.html.tmpl` (lines 22-59). Phase 8 reuses these tokens verbatim — adding new tokens would fork the design system.

**Anchors / reused surfaces:**

- v1.0 `*(suspect)*` italic suffix convention (`markdown.rs::suspect_note`, line 408) — Phase 8 emits the exact same six bytes verbatim across both surfaces.

## Spacing Scale

Declared values (already in `:root` of `index.html.tmpl`; multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-xs` | 4px | Inline gap between rank number and title; bullet-list `<li>` left padding |
| `--space-sm` | 8px | Margin between bold-label paragraph and following bullet list |
| `--space-md` | 16px | Inside-card padding; gap between consecutive cards in HTML; gap between section header and first card |
| `--space-lg` | 24px | `<section class="top-n-recommendations">` outer padding; `<details>` summary top-margin |
| `--space-xl` | 32px | Reserved for layout gaps outside this phase (header offsets) |
| `--space-2xl` | 48px | Reserved (existing report-mirror top-margin) |

**Markdown surface spacing:** GitHub-rendered Markdown handles vertical rhythm via blank lines. The card body convention is:

- One blank line between TL;DR paragraph and first `**Strengths**` label
- One blank line between each `**Label**` paragraph and its bullet list
- One blank line between consecutive bullet sections (Strengths → Weaknesses → Recommended for → Avoid for)
- `---` horizontal rule between consecutive cards (matches existing per-scenario separator convention)

**Exceptions:** none. The `.recommend-card` HTML container relies on inheritance from `.report-content` / `.report-mirror`-like wrapper styling — no new fixed-pixel rules in this phase.

## Typography

All sizes/weights inherit from the v1.0 `:root` block (lines 50-58 of `index.html.tmpl`). No new tokens introduced.

| Role | Size | Weight | Line Height | Source |
|------|------|--------|-------------|--------|
| Body (TL;DR paragraph, bullet items) | 14px (`--font-size-body`) | 400 (`--font-weight-regular`) | 1.5 (body default) | inherited from `body { ... }` rule |
| Bold label (`**Strengths**`, etc.) | 14px | 600 (`--font-weight-semibold`) | 1.5 | Markdown `**bold**` → `<strong>` (UA-styled to bold) |
| Card title (`### {rank}. {alloc}/{env_short}`) | 14px (matches `.report-mirror h3` — body-sized for compact density inside h2 section) | 600 (`--font-weight-semibold`) | 1.5 | `.report-mirror h3` precedent (line 183-187) |
| Section heading (`## Top 10 cells`) | 20px (`--font-size-heading`) | 600 (`--font-weight-semibold`) | 1.2 | `.report-mirror h2` precedent (line 178-182) |

**Markdown side (REPORT.md):**

- `## Top 10 cells` → GFM h2, GitHub-styled (typically 24px, but rendered consistently across viewers)
- `### {rank}. {alloc}/{env_short}` → GFM h3, fits inside h2 section
- `**Strengths**`, `**Weaknesses**`, etc. → bold inline labels, NOT separate headings (preserves single-h3-per-card hierarchy and avoids a 6-deep heading nest in the standalone `.md` fragments)
- TL;DR rendered as plain paragraph (no leading label — the prose self-introduces with `{alloc}/{env}` per Phase 7's `format_tldr`)

**HTML side (`recommend-cell.html.tmpl`):**

- `<article class="recommend-card" id="recommend-{rank_padded}-{alloc}-{env}">`
  - `<h3>{rank}. {alloc}/{env_short}{ if suspect_flag } *(suspect)*{ endif }</h3>`
  - `<p>{tldr}</p>` (TL;DR paragraph)
  - `<p><strong>Strengths</strong></p>`
  - `<ul>{ for s in strengths }<li>{s}</li>{ endfor }</ul>`
  - (same pattern for Weaknesses, Recommended for, Avoid for)

**Word count target:** 80-150 words per card (REQUIREMENTS CELL-05 floor/ceiling). The four bullet sections each contain 1-3 short labels (axis names or workload-class names from Phase 7's data-derived strings), so cards naturally land in this range without prose padding.

## Color

No new color tokens. Phase 8 surfaces inherit the v1.0 60/30/10 chrome declared at `:root` lines 23-30:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`--color-dominant`) | Card background; `.recommend-card` body |
| Secondary (30%) | `#F4F5F7` (`--color-secondary`) | Page sidebar (existing); section caption strip if any |
| Accent (10%) | `#0969DA` (`--color-accent`) | Reserved for: focus outline on `<details><summary>` only. NOT used for rank numbers, NOT for bullet markers, NOT for card borders. |
| Destructive | `#CF222E` (`--color-destructive`) | Reserved for existing `.suspect-note` span; Phase 8 cards do NOT use destructive directly — the `*(suspect)*` italic on the title is pure greyscale italic via `<em>` UA styling |
| Text | `#1F2328` (`--color-text`) | Card body text |
| Text muted | `#656D76` (`--color-text-muted`) | Section caption (`<p>Ranked 1-10 by composite score…</p>`) |
| Border | `#E1E4E8` (`--color-border`) | Optional 1px border on `.recommend-card` — matches existing `.chart-card` and `.report-mirror` precedent |

**Accent reserved for:** browser-native focus outline on `<details><summary>` (when keyboard-focused). Nowhere else in this phase.

**Suspect annotation rendering:**

- Markdown surface: literal six bytes ` *(suspect)*` (leading space, asterisks-italicized parenthetical) — GFM renders the asterisks as `<em>(suspect)</em>` greyscale italic inheriting `--color-text`. NO destructive color, NO `⚠` glyph in the suffix (the v1.0 `*(\u{26A0} suspect: low samples)*` form lives in REPORT.md cells; Phase 8 cards use the simpler `*(suspect)*` per CONTEXT.md decision — six bytes `(suspect)` with surrounding asterisks).
- HTML surface: same six literal bytes inside the `<h3>` text node — UA renders `*(suspect)*` as plain text (asterisks visible). NO `<em>(suspect)</em>` wrapper, NO `<span class="suspect">` badge. **Byte-identical to Markdown** for the WR-01 sentinel test.

**Heuristic-axis distinction:** out of scope for Phase 8 (the `(heuristic)` suffix and dashed gridline land in Phase 9 spider-chart axes, not in prose cards).

**Direction markers (`↑`/`↓`):** out of scope for Phase 8 (Phase 10 wires arrows into column headers and chart axis labels, not into prose cards per DIR-05 — direction markers live in headers only, never in cells).

## Copywriting Contract

All prose is **data-derived** from `CellRecommendation` fields produced by Phase 7's `recommend.rs`. Phase 8 templates do nothing beyond field substitution (REC-01 / CELL-05 contract). NO hand-edited prose strings in the templates.

| Element | Copy / Source |
|---------|---------------|
| Section heading (REPORT.md + index.html) | `Top 10 cells` — exact bytes; GFM auto-anchor `#top-10-cells` |
| Section caption | `Ranked 1-10 by composite score (equal-weighted across 8 axes). Cards 6-10 collapsed by default.` — verbatim across REPORT.md and `index.html` (with `<p>` wrap in HTML) |
| Card title pattern | `{rank}. {alloc}/{env_short}` (e.g. `1. mimalloc/debian`) — `env_short` from `recommend.rs::env_short_name()` |
| Suspect suffix | ` *(suspect)*` — leading space + literal asterisks; only annotation allowed per CELL-05 |
| TL;DR | `cell.tldr` field verbatim — single sentence prose generated by Phase 7 `format_tldr()` |
| Strengths label | `**Strengths**` (Markdown) / `<strong>Strengths</strong>` (HTML) — colon-less per CONTEXT decision (clean label, then bullets on next line) |
| Strength bullet | `- {axis_label}` — one bullet per `&'static str` in `cell.strengths` (top-2 axes) |
| Weaknesses label | `**Weaknesses**` |
| Weakness bullet | `- {axis_label}` — one bullet per `&'static str` in `cell.weaknesses` (bottom-2 axes) |
| Recommended-for label | `**Recommended for**` |
| Recommended bullet | `- {workload_class}` — one bullet per string in `cell.recommended_for` |
| Avoid-for label | `**Avoid for**` |
| Avoid bullet | `- {workload_class}` — one bullet per string in `cell.avoid_for` |
| Empty state | not applicable — `top_n_cells()` always returns 10 cells given a non-empty matrix; if fewer than 10 cells available, render whatever count Phase 7 returns (1..10). NO "no data" copy in Phase 8. |
| Error state | not applicable — render-time errors are tinytemplate compile failures (caught by `tinytemplate_compiles_index_template` test); no runtime error path |
| Destructive confirmation | not applicable — Phase 8 emits read-only static artifacts; no interactive controls, no destructive actions |
| Primary CTA | not applicable — static report; no buttons |

**Tone & voice (inherits from Phase 7 prose generators):**

- Concise, fact-based, present tense (e.g. "mimalloc/debian leads on channel throughput and web-service latency").
- No marketing language, no superlatives beyond what Phase 7's data-derived strings already contain (`format_tldr` decides phrasing — Phase 8 doesn't reshape it).
- No second-person ("you should…"), no imperative ("choose…").

**Drift defense:** `html::tests::cell_templates_both_reference_all_fields` (CELL-02) sentinel-renders both templates and asserts every `CellRecommendation` field's sentinel substring appears in BOTH outputs. Pre-empts the WR-01 winner-tiebreak drift the v1.0 fix already exposed.

## Layout & Interaction

### Card structure (one card, two surfaces)

| Component | Markdown (`recommend-cell.md.tmpl`) | HTML (`recommend-cell.html.tmpl`) |
|-----------|--------------------------------------|------------------------------------|
| Card root | None (fragment is the card) | `<article class="recommend-card" id="recommend-{rank_padded}-{alloc}-{env}">` |
| Title | `### {rank}. {alloc}/{env_short}{ if suspect_flag } *(suspect)*{ endif }` | `<h3>{rank}. {alloc}/{env_short}{ if suspect_flag } *(suspect)*{ endif }</h3>` |
| TL;DR | `{tldr}\n` (paragraph) | `<p>{tldr}</p>` |
| Strengths label | `**Strengths**\n` | `<p><strong>Strengths</strong></p>` |
| Strengths list | `{ for s in strengths }- {s}\n{ endfor }` | `<ul>{ for s in strengths }<li>{s}</li>{ endfor }</ul>` |
| Weaknesses, Recommended-for, Avoid-for | (same pattern) | (same pattern) |
| Trailing newline | `\n` (POSIX file convention) | `\n` |

### `## Top 10 cells` section composition

**REPORT.md:**

```
## Top 10 cells

Ranked 1-10 by composite score (equal-weighted across 8 axes). Cards 6-10 collapsed by default.

[card 1 body]

---

[card 2 body]

---

[card 3 body]

---

[card 4 body]

---

[card 5 body]

<details>
<summary>Show ranks 6–10</summary>

[card 6 body]

---

[card 7 body]

---

[card 8 body]

---

[card 9 body]

---

[card 10 body]

</details>
```

- Cards 1-5 always visible (Cowan's 4±1 working-memory bound, REQUIREMENTS CELL-04 rationale)
- Cards 6-10 inside a single `<details><summary>Show ranks 6–10</summary>...</details>` block (GFM-supported HTML)
- `---` horizontal rule between consecutive cards (both visible and collapsed)
- The `TOP_N_TABLE = 5` and `TOP_N_TOTAL = 10` constants from `recommend.rs` drive the cutoff — NO magic numbers in `markdown.rs`

**index.html:**

```html
<section class="top-n-recommendations">
  <h2>Top 10 cells</h2>
  <p>Ranked 1-10 by composite score (equal-weighted across 8 axes). Cards 6-10 collapsed by default.</p>

  {{ for cell in top_n_visible }}
    [card 1..5 from recommend-cell.html.tmpl]
  {{ endfor }}

  <details>
    <summary>Show ranks 6–10</summary>
    {{ for cell in top_n_collapsed }}
      [card 6..10 from recommend-cell.html.tmpl]
    {{ endfor }}
  </details>
</section>
```

- One card per row, full-width (no grid layout); cards stack vertically inside the section
- Section sits **after** the existing `<section class="report-mirror">` block, **before** any per-scenario chart drilldown blocks
- Outer container styling inherits from existing `.report-mirror` precedent (white background, `--color-border` 1px border, `border-radius: 6px`, `padding: var(--space-md)`, `grid-column: 2 / -1`)

### Standalone fragment files (`report/recommend-{rank:02d}-{alloc}-{env}.{md,html}`)

- Each `.md` file: a single rendered `recommend-cell.md.tmpl` body — no frontmatter, no `## Top 10 cells` heading, no separator. The file IS the card.
- Each `.html` file: a single `<article class="recommend-card" id="recommend-{rank:02d}-{alloc}-{env}">…</article>` — no `<html>`/`<head>`/`<body>` wrapper, no inline `<style>`. Designed for future drilldown linking (V12-04 deferred).
- Trailing `\n` on every fragment (POSIX file convention; matches existing REPORT.md/index.html style).
- Filename rank zero-padded (`01..10`) for natural filename sort. Full `{alloc}-{env}` (kebab-case ASCII validated at ingest) ensures grep-friendliness and unambiguous source-record round-trip.

| Interaction | Markdown | HTML |
|-------------|----------|------|

| Keyboard focus | Native `<details>` Tab-focus + Enter/Space toggle | Same (browser default) |
| Hover | none (no hover states in this phase) | none |
| Click target | Summary text + chevron (UA-default) | Same |

**No JavaScript** added in this phase. The disclosure widget is browser-native, file://-friendly, and matches D-02 dashboard discipline.

## Accessibility

**Semantic HTML (HTML surface):**

- `<article class="recommend-card">` — each card is an independent, self-contained piece of content (rank-ranked recommendation), eligible for syndication / drilldown linking → `<article>` is the correct landmark per HTML5 spec.
- `<h3>` for card title nested under the section's `<h2>Top 10 cells</h2>` — heading hierarchy strictly nested (h1 = page title, h2 = section, h3 = card).
- `<details>`/`<summary>` for the ranks 6-10 disclosure — browser-native, keyboard-accessible, screen-reader-announced as "expandable".
- `<ul>` for the four bullet sections — proper list semantics; screen readers announce list length and per-item context.
- `<strong>` for bold labels (NOT `<b>`) — semantic emphasis, not visual-only.

**Headings hierarchy:** h1 (`alloc-bench report` in `<header>`) > h2 (`Top 10 cells` section) > h3 (`{rank}. {alloc}/{env_short}` per card) > h2 (per-scenario chart sections, downstream of Phase 8). No skipped levels inside the cards section.

**ARIA:** No custom `aria-*` attributes added in Phase 8. The `<details>`/`<summary>` pattern is browser-native and screen-reader-supported without ARIA. Direction-marker `aria-label` wrappers (`<span aria-label="higher is better">↑</span>`) arrive in Phase 10 (DIR-04), not in this phase.

**Color contrast:**

- Body text `#1F2328` on white `#FFFFFF` → contrast ratio 14.4:1 (WCAG AAA Large + AAA Normal)
- Muted caption `#656D76` on white → 4.6:1 (WCAG AA Normal, AAA Large)
- Bold labels (semibold 600) → same `#1F2328` text color, contrast unchanged

**Focus management:**

- `<details><summary>` receives browser-default focus outline; CSS variable `--color-accent` `#0969DA` applies if a global focus rule exists (sidebar select inherits this — line 113-116 of `index.html.tmpl`). Phase 8 does NOT add per-card focus styling.

**Standalone fragment a11y:**

- The 10 standalone `.html` files are fragments designed for embedding (no `<html>`/`<head>`/`<body>`). When opened standalone, browsers render the `<article>` directly — heading hierarchy starts at h3 (acceptable for fragment context). Screen readers announce the article landmark and h3 title correctly.
- The 10 standalone `.md` files render in GitHub/IDE Markdown previewers with `### {rank}. ...` as the top heading — the previewer wraps it appropriately.

**Markdown surface a11y:**

- GFM-rendered REPORT.md inherits GitHub's accessible defaults for headings, lists, and `<details>` widgets. No additional concerns for this phase.

## Cross-Surface Byte-Identity Contract

Phase 8's defining discipline: a single `CellRecommendation` struct → two outputs (Markdown + HTML) that are field-by-field identical. The WR-01 sentinel test (`html::tests::cell_templates_both_reference_all_fields`, CELL-02) enforces this at compile/test time.

**Verifiable invariants:**

1. Both templates reference all 11 `CellRecommendation` fields (rank, alloc, env, composite_score, axes, tldr, strengths, weaknesses, recommended_for, avoid_for, suspect_flag) — sentinel-rendered substrings appear in both outputs.
2. The `*(suspect)*` annotation emits the exact same six bytes `(suspect)` between asterisks across both surfaces — no `<em>(suspect)</em>` wrapper in HTML.
3. The section caption `Ranked 1-10 by composite score (equal-weighted across 8 axes). Cards 6-10 collapsed by default.` is byte-identical across REPORT.md (plain text + blank line) and index.html (`<p>...</p>` wrapped). HTML wrap is the only delta.
4. Bullet content (axis labels, workload classes) is plain text — DEFAULT tinytemplate formatter HTML-escapes `<`/`>`/`&`/`"` on the HTML side; Markdown side escapes nothing (those characters are valid in Markdown body text).
5. Trailing newline `\n` on every standalone fragment file (POSIX convention).
