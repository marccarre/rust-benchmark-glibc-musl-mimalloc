normalize_axis algorithm (locked):
1. Filter non-finite inputs: any `!x.is_finite()` element causes that slot to be replaced with `0.0` (mirrors `multi_run::aggregate`'s `is_finite` guard at multi_run.rs:67-69).
2. Empty input → return `Vec::new()`.
3. Single-value input → return `vec![50.0]` (deterministic mid-range).
4. All-equal input (max - min ≤ 1e-12 after p10/p90) → return `vec![50.0; n]` (avoid div-by-zero).
5. Sort copy of inputs ascending; compute `p10 = sorted[floor(0.10 * n)]` and `p90 = sorted[floor(0.90 * n).min(n-1)]`. At N=18: `floor(1.8) = 1` and `floor(16.2) = 16`. Clamp every input to `[p10, p90]`.
6. Min-max with p10/p90 as the range: `score_raw = (clamped_value - p10) / (p90 - p10) * 100.0`.
7. Direction inversion: if `direction == Direction::Lower`, score = `100.0 - score_raw`.
8. Hard clamp output to `[0.0, 100.0]`.

compute_axes algorithm (locked):
- Group `runs` by `(alloc, env)` cell. Discover cells from the union of `runs` keys + `cell_metas` keys + (Cartesian product of allocs × envs from `security_metas`) — but the simpler path used here: enumerate cells from runs only (every cell with image-size + security metadata also has runs in production; absence of runs = absence of cell). Use `BTreeMap<(String, String), Vec<&Run>>` for alphabetical iteration.
- For each cell, compute the 6 measured axes via `multi_run::aggregate` over the matching scenarios:
    - `channel_throughput` ← median across spmc + mpsc + mpmc throughputs (mean of three medians; Higher)
    - `cpu_bound_throughput` ← median of cpu-bound throughputs (Higher)
    - `memory_fragmentation` ← mean of mem-bound + fragmentation-soak peak_rss_kb (Lower)
    - `multithread_throughput` ← median of multithread throughputs (Higher)
    - `resilience` ← mean of realloc-storm + contention throughputs (Higher)
    - `web_throughput` ← median of web throughputs (Higher)
- For the 2 heuristic axes:
    - `image_size_efficiency` ← `cell_metas.get(&(alloc, env)).map(|m| m.image_size_mb).unwrap_or(0.0)` then INVERTED later via Direction::Lower? — NO: per RESEARCH §1 + axes.rs spec, `image_size_efficiency` direction is Higher. Smaller image == higher efficiency, so the raw value MUST be negated or pre-inverted. Implementation: store raw image_size_mb, then in compute_axes after collecting all 18 cells, normalize_axis is called with `Direction::Lower` for image_size and `Direction::Higher` for security. Wait — axes.rs declares `image_size_efficiency` as `Direction::Higher`. Reconcile: the SCORED axis is "efficiency" (Higher = better); the RAW value collected from `cell_metas` is `image_size_mb` (Lower = better). Solution: collect raw `image_size_mb` per cell, pass through `normalize_axis` with `Direction::Lower` (smaller MB → higher score), then store under the key `image_size_efficiency`. The axis spec's `Direction::Higher` describes the SCORE direction (post-normalization), not the raw input.
    - `security_posture` ← `security_metas.get(&env).map(|m| m.score as f64).unwrap_or(0.0)`. Direction::Higher (raw score: higher = better).
- After computing the 8 raw values per cell, build per-axis vectors of length 18 (one entry per cell, alphabetical `(alloc, env)` order). Run `normalize_axis` on each vector with the axis's effective direction (NOT axes.rs `Direction::Higher` for image_size — see above). Result: 8 normalized vectors of length 18.
- Stitch back into `Vec<CellAxes>` of length 18, alphabetical: each cell carries a `BTreeMap<&'static str, f64>` keyed by `MEASUREMENT_AXES[i].key`, value is the normalized score (0..=100).

score_cells algorithm (locked, SCORE-03 + TEST-04):
- For each `CellAxes`, compute composite: `MEASUREMENT_AXES.iter().map(|spec| cell.axes.get(spec.key).copied().unwrap_or(0.0) * 0.125).sum::<f64>()`. Iterator-traversal mandatory (NOT collected `Vec` — see RESEARCH §5).
- Output preserves input order (alphabetical from compute_axes).

top_n algorithm (locked, SCORE-04):
```rust
let mut sorted = scores;
sorted.sort_by(|a, b| {
    b.composite.partial_cmp(&a.composite)
        .unwrap_or(std::cmp::Ordering::Equal)
        .then_with(|| a.alloc.cmp(&b.alloc))
        .then_with(|| a.env.cmp(&b.env))
});
sorted.truncate(n);
sorted
```

Edge-case handling for compute_axes — NaN propagation (TEST-05):
- A run with `metrics.ticks_per_s = NaN` (or any non-finite metric used for an axis) is fed into `multi_run::aggregate`, which already returns `None` per multi_run.rs:67. When `aggregate` returns `None` for an axis, fall back to `0.0` (sentinel). Then `normalize_axis` filters that 0.0 like any other low value. The cell is NOT dropped — option (a) sentinel-value path is selected over option (b) drop-cell because dropping a cell would change the 18-cell count and break Phase 9 polar.rs assumptions about top_n.
- Crucially: `partial_cmp` on NaN returns `None`; `unwrap_or(Equal)` keeps the alphabetical secondary sort firing as last-resort tiebreak. Test `nan_input_does_not_corrupt_score` asserts that an NaN-fed cell does NOT outrank a finite-score cell.
