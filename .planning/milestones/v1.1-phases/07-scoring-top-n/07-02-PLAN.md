```rust
/// True if ANY run in the cell trips html::is_suspect (samples<1000 OR warmup<5s).
/// Generic IntoIterator form so callers can pass `&[Run]` (slices) OR `Vec<&Run>`
/// without cloning Run (which does not derive Clone per the v1 schema GUARD-01).
fn cell_is_suspect<'a, I: IntoIterator<Item = &'a Run>>(cell_runs: I) -> bool {
    cell_runs.into_iter().any(|r| is_suspect(&r.harness))
}

/// Returns `MEASUREMENT_AXES[i].label` (NOT key) — human-facing prose.

/// Single-sentence: `"{alloc}/{env} — strong on {top_strength_label}, weak on {bottom_weakness_label}."`.

fn format_tldr(alloc: &str, env: &str, strengths: &[&'static str], weaknesses: &[&'static str]) -> String;

/// For this `(alloc, env)` cell, return alphabetical class labels where it wins per existing `recommendations(runs)`.
/// Re-uses winner detection; does NOT re-use rationale strings.
fn derive_recommended_for(alloc: &str, env: &str, runs: &[Run]) -> Vec<&'static str>;

/// For this `(alloc, env)` cell, return alphabetical class labels where it finishes in the bottom 2
/// across the 18-cell ranking for that class. Class ranking is per-scenario throughput-mean (mirrors
/// the AllocStats logic in recommend_for_class), but bottom-2 needs the FULL cell ranking, not just
/// the top winner. Implementation: for each WorkloadClass, build a Vec<(alloc, env, mean_throughput)>
/// across all cells in `runs`, sort DESC, identify the bottom 2 by tail-end position; if `(alloc, env)`
/// is in the bottom 2 (and the class has ≥2 measured cells), include the class label.
fn derive_avoid_for(alloc: &str, env: &str, runs: &[Run]) -> Vec<&'static str>;
```

Algorithm — `top_n_cells` (locked):
1. Compute `top_scores = score::top_n(scores, TOP_N_TOTAL)` → at most 10 cells, `(composite DESC, alloc ASC, env ASC)`.
2. Pre-compute `recommended_winners: BTreeMap<&'static str, BTreeSet<(String, String)>>` from a single pass over `recommendations(runs)` — for every class label, store the winning `(alloc, env)` cells. This avoids running the winner picker N times. NOTE: existing `Recommendation.allocator` is a `String` like `"jemalloc"` or `"(only ptmalloc measured)"` — for the cell-level recommended_for, we need the FULL `(alloc, env)` tuple, not just allocator. Implementation hint: re-implement a thin per-class winner picker that returns `Option<(alloc, env)>` for each class, OR reach into `recommend_for_class` indirectly. PREFERRED: write a private `winners_by_class(runs: &[Run]) -> BTreeMap<&'static str, BTreeSet<(String, String)>>` helper that iterates `ALL_CLASSES`, groups runs by `(alloc, env)` per class, computes per-cell mean across class scenarios, and emits the (alloc, env) pair with the maximum mean as the class winner. Tied cells break alphabetically by `(alloc, env)` (matches existing recommend_for_class BTreeMap iteration).
3. Pre-compute `bottom_2_by_class: BTreeMap<&'static str, BTreeSet<(String, String)>>` similarly — for each class, identify the 2 cells with the lowest mean across class scenarios (alphabetical tiebreak on `(alloc, env)`). If a class has fewer than 2 measured cells, it contributes no entries.
4. For each cell in `top_scores`, build a `CellRecommendation`:
   - `rank: i + 1` (1-indexed iteration counter)
   - `alloc`, `env`, `composite_score`, `axes` copied from the `CellScore`
   - `strengths = derive_strengths(&cell.axes)` — top-2 labels
   - `weaknesses = derive_weaknesses(&cell.axes)` — bottom-2 labels
   - `tldr = format_tldr(&cell.alloc, &cell.env, &strengths, &weaknesses)`
   - `recommended_for`: collect class labels where `recommended_winners[class].contains(&(cell.alloc, cell.env))`. Output sorted alphabetically (the BTreeMap iteration already gives this).
   - `avoid_for`: collect class labels where `bottom_2_by_class[class].contains(&(cell.alloc, cell.env))`. Output sorted alphabetically.
   - `suspect_flag`: filter `runs` to those matching `(alloc, env)` for this cell, then `cell_is_suspect(&matching_runs)`.

Algorithm — `derive_strengths` (locked):
- Build `Vec<(&'static str, f64)>` where the first element is `axis_key` (looked up from `MEASUREMENT_AXES`) and the second is the cell's normalized score.
- Sort DESCENDING by score; on tie (`(a.1 - b.1).abs() < 1e-12`), break alphabetically on `axis_key` (`a.0.cmp(&b.0)`).
- Take first 2 entries; map `axis_key` → `MEASUREMENT_AXES.iter().find(|s| s.key == key).unwrap().label`.
- Return `Vec<&'static str>` of length 2 (or fewer if `axes` has fewer than 2 entries — defensive).

Algorithm — `derive_weaknesses` (locked):
- Same as `derive_strengths` but sort ASCENDING, take first 2 (the lowest two), still alphabetical tiebreak on key.

Algorithm — `format_tldr` (locked):
- Returns `format!("{}/{} — strong on {}, weak on {}.", alloc, env, strengths[0], weaknesses[0])`.
- Defensive: if `strengths.is_empty()`, use `"insufficient data"` for the strength slot; same for weaknesses. This path is unreachable for production data (8 axes always present) but guards against test fixtures with fewer cells.
- Em-dash glyph `\u{2014}` (U+2014) is the same em-dash already used by the existing `recommend_for_class` no-measurements path at recommend.rs:144,205 — per RESEARCH §6 example: `"jemalloc/alpine — strong on CPU-bound throughput, weak on Memory / fragmentation."`. NOTE: the literal em-dash unicode in the format string is required; do not substitute a hyphen.
