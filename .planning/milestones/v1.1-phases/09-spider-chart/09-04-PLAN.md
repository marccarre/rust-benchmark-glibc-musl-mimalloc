# Plan 09-04 — Spider Chart Small-Multiples Refactor

> Gap closure plan for the UI-REVIEW BLOCKER (single overlay polar chart vs the three small-multiples grid required by 09-UI-SPEC.md / 09-CONTEXT.md). Closes WR-01..WR-06 (6 warnings) as a natural consequence of the BLOCKER fix.

## Goal

Refactor the spider section in `templates/index.html.tmpl` and `crates/alloc-bench-aggregator/src/html.rs` to render **three independent `<div class="spider-cell">` containers** in a flex grid, each receiving its own `Plotly.react` call with one matrix-mean reference trace + one cell trace. Apply the missing CSS layout properties and the per-tick `tickfont.color` array. All as documented in `09-UI-REVIEW.md` "Top 3 Priority Fixes" + Pillars 2-5 detailed findings.

**Success criteria:**

1. `index.html.tmpl` contains three `<div class="spider-cell" id="spider-cell-1">`, `id="spider-cell-2"`, `id="spider-cell-3"` divs inside `<div id="chart-spider" class="spider-grid">`.
2. The inline `<script>` issues three independent `Plotly.react(...)` calls, one per spider-cell.
3. CSS at `index.html.tmpl` styles:
   - `.spider-grid { display: flex; flex-wrap: wrap; gap: var(--space-md); }`
   - `.spider-cell { background: var(--color-dominant); border: 1px solid var(--color-border); border-radius: 6px; padding: var(--space-md); flex: 1 1 calc((100% - 2 * var(--space-md)) / 3); aspect-ratio: 1 / 1; min-width: 280px; }`
   - `.spider-chart h2 { margin: 0 0 var(--space-sm) 0; }` (was `--space-md`)
   - `.spider-chart p { color: var(--color-text); }` (was `--color-text-muted`)
   - Mobile override: `@media (max-width: 768px) { .spider-cell { flex-basis: 100%; } }` added to existing `@media` block.
4. `html::build_spider_context` returns a struct with `Vec<String>` of three per-cell-trace-pair JSON strings (each = `[reference_trace, cell_trace]`) instead of a single combined `traces` string. Field renamed to `spider_cells_json: Vec<String>` (or kept as a comma-joined string for tinytemplate; pick whichever is cleanest).
5. Each per-cell `Plotly.react` call passes a per-cell `layout` JSON that includes `layout.title.text = "{alloc}/{env}"` with `font: { size: 14, color: "#1F2328" }`.
6. The `tickfont.color` is a per-tick array `["#222","#222","#666","#222","#222","#222","#666","#222"]` (indices computed by iterating `MEASUREMENT_AXES` and emitting `"#666"` for `is_heuristic == true`, `"#222"` otherwise — keeps the array in sync if MEASUREMENT_AXES changes).
7. All 161 aggregator tests still pass. Add at least one new test:
   - `html::tests::spider_section_emits_three_spider_cell_divs` — asserts exactly 3 occurrences of `class="spider-cell"` in rendered HTML.
   - `html::tests::angular_axis_tickfont_color_is_per_tick_array` — asserts the layout JSON contains the 8-element color array with `#666` at indices 2 and 6.
   - `tests/smoke.rs::three_spider_cells_present_when_data_exists` — smoke-level confirmation that 3 spider-cell divs render in the `report/index.html` output.
8. The existing tests `spider_traces_json_contains_scatterpolar_type` and `plotly_sri_hash_unchanged_full_string` continue to pass (refactor must keep the JSON shape per-cell — type still `scatterpolar`, `fill: "toself"`, etc.).

- Golden fixtures — Phase 11 owns regen; this plan should NOT regenerate fixtures. If a golden test fails on the new HTML output, that test is stale and should be updated in Phase 11. Document the expected fixture diffs in the SUMMARY.

## Anti-patterns to avoid

- **Removing `<div id="chart-spider">`:** the smoke test `spider_div_present_when_data_exists` checks for this id. Keep the OUTER div with `id="chart-spider" class="spider-grid"`, and add the THREE INNER `<div class="spider-cell">` children.
- **Per-cell title injected via Plotly `layout.title`:** do NOT add HTML `<h3>` elements per cell. The spec puts the title inside the chart via Plotly's `layout.title.text` field. This keeps the chart self-contained for screenshot/export.
- **Adding a 4th hidden chart for the reference polygon:** the reference polygon should be the FIRST trace inside each of the three cells (so it renders behind the cell polygon). Do NOT add a 4th chart.
- **Mutating MEASUREMENT_AXES:** the heuristic-axis indices (2 and 6) come from iterating MEASUREMENT_AXES at build time; do NOT hard-code [2, 6] in the template or html.rs.
- **Skipping the regression gate:** every commit in this plan must be followed by `cargo test -p alloc-bench-aggregator` to confirm 161+ tests still pass.
