Append a new recipe block to the END of `justfile` (after `ci-aggregate`, with a `# ──────────────────────────────────────────────────────────────────────` section header for `Pages publishing`). Recipe name: `publish-pages` (no args).

Recipe body MUST:

1. Use the established recipe-block style — leading comment block describing usage and the gh-pages branch model, recipe header `publish-pages:`, body starting with `#!/usr/bin/env bash` and `set -euo pipefail`.

2. **Fail fast on missing input.** First runtime check: `if [ ! -f report/index.html ]; then echo "[ERR] report/index.html does not exist; run 'just aggregate' first to generate the dashboard." >&2; exit 1; fi`. Do NOT auto-run `just aggregate`.

3. **Capture source ref for commit message.** `SRC_SHA=$(git rev-parse --short HEAD)` and `SRC_BRANCH=$(git rev-parse --abbrev-ref HEAD)` BEFORE creating the worktree (so the values reflect the user's working tree, not the gh-pages worktree).

4. **Create a temp worktree dir + trap cleanup.** Use `WORKTREE_DIR=$(mktemp -d -t gh-pages-XXXXXX)` for the worktree path. Register cleanup BEFORE the worktree is created so even a failure between mktemp and `worktree add` is handled:
   ```
   cleanup() {
       if git worktree list --porcelain 2>/dev/null | grep -q "$WORKTREE_DIR"; then
           git worktree remove --force "$WORKTREE_DIR" 2>/dev/null || true
       fi
       rm -rf "$WORKTREE_DIR"
   }
   trap cleanup EXIT
   ```

5. **Idempotent worktree creation.** The recipe must work whether `gh-pages` exists nowhere, only on remote, or both:
   - First, fetch any remote `gh-pages` so we know its state: `git fetch origin gh-pages:gh-pages 2>/dev/null || true` (the `:gh-pages` form creates the local branch tracking the remote). The `|| true` is critical — fresh repos have no remote `gh-pages` yet and the fetch will fail; that's expected.
   - Branch into three cases:
     - If `git show-ref --verify --quiet refs/heads/gh-pages` succeeds → branch exists locally → `git worktree add "$WORKTREE_DIR" gh-pages`.
     - Else if `git ls-remote --exit-code --heads origin gh-pages` succeeds → branch exists on remote but the fetch did not create the local ref (rare; defensive) → `git worktree add -b gh-pages "$WORKTREE_DIR" origin/gh-pages`.
     - Else → first publish ever → `git worktree add --orphan -b gh-pages "$WORKTREE_DIR"` and then `(cd "$WORKTREE_DIR" && git rm -rf . 2>/dev/null || true)` to clear any inherited tracked files (orphan branches can still inherit the working tree's index in some git versions; the `rm -rf .` is the documented `git`-recommended hygiene step).

6. **Copy ONLY `report/index.html`.** `cp report/index.html "$WORKTREE_DIR/index.html"`. Do NOT copy `report/REPORT.md` or any other file. Do NOT use `cp -r report/`.

7. **Commit + push from inside the worktree.** Use a subshell `(cd "$WORKTREE_DIR" && ...)` to avoid changing the parent shell's CWD:
   ```
   (
       cd "$WORKTREE_DIR"
       git add index.html
       if git diff --cached --quiet; then
           echo "[publish-pages] no changes to publish (index.html identical to gh-pages HEAD)"
       else
           git commit -m "Publish dashboard from ${SRC_BRANCH}@${SRC_SHA}"
           git push origin gh-pages
       fi
   )
   ```
   The `if git diff --cached --quiet` guard makes the recipe a no-op-but-success when re-run with no dashboard changes (instead of failing on `git commit` with "nothing to commit").

8. **Print the URL hint** as the LAST line before exit: `echo "[publish-pages] published — visit https://marccarre.github.io/rust-benchmark-glibc-musl-mimalloc/ (may take a minute on first publish)"`.

Do NOT touch any existing recipe. Do NOT add or modify any GitHub Actions workflow files. Do NOT modify `report/index.html` generation.

Implementation note on the comment block: include a one-paragraph explanation of why this recipe exists (HTML dashboard + .gitignored report/ + no GHA workflow), the prerequisite (`just aggregate` must have run), and a one-line URL pointer to the published site. Pattern matches the `bench-all` and `ci-bench-cell` comment-block density.
